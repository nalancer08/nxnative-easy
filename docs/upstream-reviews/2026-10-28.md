Reviewed and merged 160 commits reachable from upstream main, including its merge history; no unrelated open PR was imported. Upstream authors remain in history. Our merge retains the Easy frontend and bilingual README instead of replacing them with upstream’s player page.

## Accepted changes

- 20 added profiles and five changed profile definitions; 98 profiles total. Artwork, search inventory and both README galleries are generated together. Regional profiles retain explicit title-ID artwork mappings.
- Graphics fixes for indirect draws, geometry, sparse textures, presentation crops, pipeline caches and the shared shader-library ABI. Chain `fda42ce035db` uses its locked translator and Metal compilers.
- Per-player iOS physical controllers, controller/phone gyro and rumble improvements, Home/Capture handling and playback audio that survives the silent switch.
- Safer NSO/file-parser validation, NSZ executable fallback, extraction prerequisites, AppleDouble handling, incremental shader/cache changes, diagnostics and developer checks.

## Fork resolutions

- Keep our touch editor and all four named per-game profiles. Cancel an active edit safely when a physical controller connects; preserve upstream player-slot input and motion behavior.
- Do not import the startup deletion of legacy Documents/romfs. Both folder/image boot paths retain external content and save bytes; full bundles honor DMPreferBundledRomFS before stale external content.
- Keep Easy’s directory extraction until its splitter, prepared records and native folder-transfer protocol can migrate together. The upstream CLI retains image extraction; Mac frontend outputs remain complete apps and iOS frontend outputs retain optional lightweight export.
- Keep CNMT/NACP metadata-only identification, stale-input refusal, live progress/logs, local save export, scoped device presence, installer consent/identity checks, shared Keychain sessions and bilingual Settings/navigation.
- Retain one bilingual gallery writer. Parse upstream bold captions without duplicating game titles and normalize empty-note placeholders so regeneration is idempotent. Quote both native-test paths that contain spaces.
- Xcode 27.1/macOS 26.6+ are the reviewed game-build requirements. Both bootstrap entry points stop early on older Xcode; the compiler lock still checks the actual Metal compiler. Updating the frontend does not recompile existing games automatically.

## Validation

- Fork workflow suite: 76 tests (four platform/optional skips), plus targeted catalog/metadata/content-preservation tests; live SwiftUI models use synthetic accounts/devices only.
- 84 upstream Python test modules: 716 tests, 12 documented skips; the CI toolchain mismatch was corrected and its module rerun successfully. No remaining failed module.
- Mac host compile and complete host unit-test run; complete native GPU test run on this Mac with Metal validation.
- Production iOS app compile/link using synthetic modules, unsigned and without any Apple login or device installation.
- Locked shader tools verified. Separate real Dread rebuild: 1,010/1,010 shaders, 359 pulling variants, no failed compilation, Mac and iOS outputs. Host rebuilt after generated profile tables.
- Read-only real metadata check: Metroid Dread base 1.0.0 and update 2.1.0 (internal 327680). Original archives, working IPA, RomFS and saves were not replaced.
- Catalog/documentation checks and Python lint ratchet; no new lint findings.

**Limit:** the gameplay regression harness was invoked, but no registered Mac game build (`<id>_build/tools/dmhost`) exists in the local game folders. It could not run a before/after gameplay route. The host/GPU tests and shader rebuild are not a claim that all games work on iPhone. Jamboree’s upstream note explicitly reports Mac-only testing and no built iPhone IPA. New profiles require each user’s own files and keys.
