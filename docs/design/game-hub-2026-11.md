# A game-centred home, 1.27

The brief is comprehension: show where a game is, why it needs attention, which
Easy release prepared/signed it and what to do with its progress. Extend the
existing SwiftUI system; retain actual artwork, account/identity guards and
local/cloud save boundaries. Avoid a second device-management catalogue.

This iteration reuses the four-platform research actually inspected earlier in
this conversation: [the cinematic launcher references](cinematic-frontend-2026-11.md)
and [save-transfer references and provenance](save-transfer-2026-11.md). The
Foundation Lab/Oniex desktop compositions inform the selected-game dossier; the
Juxtopposed Steam library keyframes inform context-sensitive actions; WeTransfer's
preview/copy distinction and the Time Machine history excerpt inform save review.
Those records identify authors, links, observed media and access limits. No new
visit or full-video viewing is claimed here. No external UI asset was copied.

The home keeps game artwork as a stage, with a restrained device/care dossier
beside it and a smaller shelf carrying per-game attention labels. The persistent
connection strip replaces the Devices destination. Details separate My game from
Saves and backups so provenance does not bury copy actions. Midnight/cyan/violet
tokens, native controls, semantic warnings, reduced-motion shelf transitions and
the existing local Lottie remain shared. The original generated save-vault art
is reused in the new per-game save tab; its prompt is in the transfer record.

Native screenshots use synthetic games, device names and signing records in
English/Spanish at 1160×800 and 1000×640. Business tests cover missing history,
expiry priority, different content, irrelevant launcher changes, provenance
association and new-file-only backups. No live account, signing, install, device
export, active restore or iCloud delivery is implied by those fixtures.
